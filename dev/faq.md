# How do I…? Questions and answers

Short answers to frequent questions, with a code example and links to the manuals. The examples are client-server Eliom code (in `.eliom` files). They assume:

```ocaml
open%shared Eliom.Content.Html.F
```
and use the Lwt syntax extension (`let%lwt`, see [Lwt in 5 minutes](./lwt.md)). Answers mentioning `Os` or `Ot` use `Ocsigen Start` and `Ocsigen Toolkit`. Module names are those of Eliom 13 and later (`Eliom.Service` rather than `Eliom_service`, see [the migration guide](./migration.md)).

Pages are registered with the module `App` of the application, made by `Eliom.Registration.App`: it is in `myapp.eliom` with the `app` template, and is `Myapp_base.App` with the `os` template. Do not use `Eliom.Registration.Html` for the pages of a client-server application: it sends them without the client-side program, so their client-side code does not run, and links towards them leave the application.

## Getting started

### How do I create my first application?

Generate it with `eliom-distillery`:

```sh
eliom-distillery -name myapp -template os   # Ocsigen Start: users, database, mobile app
eliom-distillery -name myapp -template app  # Eliom only, a smaller start
```
The `os` template shows an example of almost every feature of Ocsigen (see [Your first app in 5 minutes](./start.md)). Then follow the `README.md` of the generated project. A page is produced by a *service*, registered with a handler:

```ocaml
let%server hello =
  App.create
    ~path:(Eliom.Service.Path ["hello"])
    ~meth:(Eliom.Service.Get Eliom.Parameter.unit)
    (fun () () ->
       Lwt.return
         (html
            (head (title (txt "Hello")) [])
            (body [h1 [txt "Hello, world!"]])))
```
To understand how an application is organised, read the [client-server application programming guide](./basics.md), or the [server-side website programming guide](./basics-server.md) if you do not need client-side code.

### How do I compile and run it?

The generated projects build with dune. The `app` template runs with `dune build` then `dune exec myapp`; the `os` template with `make db-init db-create db-update` (once) then `make test.byte`. Details are in the `README.md` of the project and in the `distillery manual`.

The client-side code is compiled to JavaScript, and to WebAssembly if you call `Eliom.Config.set_enable_wasm true` (the templates do): the server then sends the WebAssembly version to the browsers that support it.

### How do I configure and launch Ocsigen Server?

Two ways, both generated by the templates:

- with a configuration file: `ocsigenserver -c myapp.conf` (see the `configuration file documentation`);
- as a library: your executable calls `Ocsigen.Server.start` with the options and the extensions to load (see `this section of Eliom's manual`).

## Pages and HTML

### How do I write HTML?

One OCaml function per element. The content is a list, and attributes go in the optional `~a` argument. The compiler checks that the HTML is valid:

```ocaml
let%shared fruits =
  div
    ~a:[a_class ["card"]; a_id "fruits"]
    [ h2 [txt "Fruits"]
    ; p [txt "Some "; em [txt "fresh"]; txt " fruits:"]
    ; ul [li [txt "Banana"]; li [txt "Kiwi"]]
    ; Raw.select
        [option (txt "Small"); option ~a:[a_selected ()] (txt "Large")] ]
```
Form elements towards a service are typed and come from module `Form` (see [below](./#forms)). Their `Raw` versions are plain HTML elements, for instance for a form handled by client-side code. `F` creates functional nodes and `D` nodes that the client-side code can refer to. Everything is explained in [HTML in 5 minutes](./html.md). The element functions are those of `TyXML`.

### How do I share the same layout between pages?

Write a function that builds the page around its content:

```ocaml
let%shared static path = make_uri ~service:(Eliom.Service.static_dir ()) path

let%shared skeleton ~title:t content =
  html
    (head
       (title (txt t))
       [ css_link ~uri:(static ["css"; "app.css"]) ()
       ; js_script ~uri:(static ["js"; "chart.js"]) ()
       ; link ~rel:[`Icon] ~href:(static ["favicon.png"]) () ])
    (body [header [h1 [txt t]]; div ~a:[a_class ["content"]] content])
```
The `os` template already has one: `Myapp_container.page`.

### How do I add a stylesheet, a script or a favicon?

In the `head` of the page, as in the [skeleton above](./#skeleton): `css_link`, `js_script` and `link ~rel:[`Icon]`, with links towards the static directory (see [below](./#static)). Without the `link` element, browsers look for `favicon.ico` at the root of the site. The `os` template compiles SASS files from directory `sass/` into a CSS file.

For client-side code, you do not need to add scripts yourself: Eliom adds the program of the application to the page.

### How do I link to an image (or another static file)?

Static files are served from the directory given in the configuration file (directory `static/` of the project with the templates). The predefined service `Eliom.Service.static_dir` builds links towards them. In a mobile application, each image is either embedded in the application or fetched from the server:

```ocaml
let%shared images =
  [ (* in the static directory, embedded in the mobile app: *)
    img ~alt:"Logo"
      ~src:
        (make_uri ~absolute:false
           ~service:(Eliom.Service.static_dir ())
           ["images"; "logo.png"])
      ()
  ; (* in the static directory, always fetched from the server: *)
    img ~alt:"Banner"
      ~src:(make_uri ~service:(Eliom.Service.static_dir ()) ["images"; "banner.jpg"])
      ()
  ; (* anywhere on the Web: *)
    img ~alt:"OCaml" ~src:(Xml.uri_of_string "https://ocaml.org/logo.svg") () ]
```
On the Web, both `static_dir` links are relative and give the same result. In the mobile app, links are absolute by default, so they point to the server. With `~absolute:false`, the link stays relative and the image is read from the files embedded in the app: the `os` template embeds the directories `css`, `images` and `fonts` of `static/`. Use it for the images that are part of the interface (logo, icons); keep the default for the ones that change after the app is installed, such as images uploaded by users. See also `how Ocsigen Server serves static files`.

## Services, links and forms

### How do I take parameters from the URL?

The parameters of a service are declared with the combinators of `Eliom.Parameter`, and the handler receives them already decoded and typed. They can be in the query string or in the path (`suffix`):

```ocaml
(* /search?q=ocaml&page=2 *)
let%server search =
  Eliom.Service.create
    ~path:(Eliom.Service.Path ["search"])
    ~meth:
      (Eliom.Service.Get Eliom.Parameter.(string "q" ** opt (int "page")))
    ()

(* /user/alice *)
let%server user =
  Eliom.Service.create
    ~path:(Eliom.Service.Path ["user"])
    ~meth:(Eliom.Service.Get Eliom.Parameter.(suffix (string "name")))
    ()

let%server () =
  App.register ~service:search (fun (q, page) () ->
    let page = Option.value page ~default:1 in
    Lwt.return
      (skeleton ~title:"Search"
         [p [txt (Printf.sprintf "Results for %s, page %d" q page)]]));
  App.register ~service:user (fun name () ->
    Lwt.return (skeleton ~title:name [p [txt ("Profile of " ^ name)]]))
```
Several parameters are combined with `**`, and the handler receives nested pairs: `(a, (b, c))`. The second argument of the handler is for POST parameters. Other types are `int32`, `int64`, `float`, `bool`, `list`, `set`, `user_type`, and more: see the manual on `service parameters` and on `services`.

### How do I make links?

Links towards a service are typed: give the service and the values of its parameters.

```ocaml
let%server ocaml_org =
  Eliom.Service.extern ~prefix:"https://ocaml.org" ~path:["docs"]
    ~meth:(Eliom.Service.Get Eliom.Parameter.unit) ()

let%server links =
  [ a ~service:search [txt "Search for OCaml"] ("OCaml", None)
  ; a ~service:user [txt "Alice's profile"] "alice"
  ; a ~service:ocaml_org [txt "OCaml documentation"] ()
  ; Raw.a ~a:[a_href (Xml.uri_of_string "https://ocaml.org")] [txt "ocaml.org"]
  ; (* the current page: *)
    a ~service:Eliom.Service.reload_action [txt "Reload"] () ]
```
`Eliom.Service.reload_action` links to the current page, whatever its URL. In a client-server application, clicking a link towards a service of the application changes page without leaving the client-side program. For a service that does not send a page of the application (a file, JSON...), add `~xhr:false`: otherwise the client-side program first requests it, then is told to leave the application and load it again. See `links and forms`.

### How do I write a form?

Like links, forms are typed. The function given to `Form.get_form` or `Form.post_form` receives the names of the parameters of the service, and each field must have the type of its parameter:

```ocaml
let%server search_form =
  Form.get_form ~service:search (fun (q, page) ->
    [ Form.input ~input_type:`Text ~name:q Form.string
    ; Form.input ~input_type:`Number ~name:page Form.int
    ; Form.input ~input_type:`Submit ~value:"Search" Form.string ])

let%server comment =
  Eliom.Service.create
    ~path:(Eliom.Service.Path ["comment"])
    ~meth:
      (Eliom.Service.Post
         (Eliom.Parameter.int "post_id", Eliom.Parameter.string "text"))
    ()

(* The GET parameters of a POST form come last. *)
let%server comment_form post_id =
  Form.post_form ~service:comment
    (fun text ->
       [ Form.textarea ~name:text ()
       ; Form.input ~input_type:`Submit ~value:"Send" Form.string ])
    post_id
```
`Form` also has `select`, `checkbox`, `radio`, `file_input`... See `forms in Eliom's manual` and the `demo_forms.eliom` file of the `os` template. The `os` template also shows how to submit a form from client-side code, without changing page.

### How do I write a service that answers any path, takes any parameter and returns anything?

Take the end of the path with `all_suffix` and all parameters with `any`, then register with `Eliom.Registration.String`, which sends a string with the content type of your choice:

```ocaml
let%server anything =
  Eliom.Service.create
    ~path:(Eliom.Service.Path ["api"])
    ~meth:
      (Eliom.Service.Get Eliom.Parameter.(suffix_prod (all_suffix "path") any))
    ()

let%server () =
  Eliom.Registration.String.register ~service:anything
    (fun (path, params) () ->
       let params = List.map (fun (k, v) -> k ^ "=" ^ v) params in
       Lwt.return
         ( Printf.sprintf "path: %s\nparameters: %s\n"
             (String.concat "/" path) (String.concat ", " params)
         , "text/plain" ))
```
This service answers `/api/x/y?a=1&b=2` with `path = ["x"; "y"]`, and `params` contains `("a", "1")` and `("b", "2")` (do not rely on their order). Services with a more specific path, such as `/api/users`, keep priority. With `~path:(Eliom.Service.Path [])`, the service answers every URL of the site that no other service takes: the extensions placed after `<eliom/>` in the configuration file no longer see them, so put `<static>` before. For POST requests, register a second service with `Eliom.Service.Post`.

To send different kinds of content depending on the request (a page, a file, a redirection...), register with `Eliom.Registration.Any`, as in the [next question](./#choose).

### How do I send a page or a file, depending on the request?

Register with `Eliom.Registration.Any`: the handler calls the `send` function of the output module of its choice. Here, a file, or a page of the application saying that it does not exist:

```ocaml
let%server files_dir = "/var/www/files"

let%server download =
  Eliom.Registration.Any.create
    ~path:(Eliom.Service.Path ["download"])
    ~meth:(Eliom.Service.Get Eliom.Parameter.(string "name"))
    (fun name () ->
       (* basename: never let a user choose a path on your disk *)
       let file = Filename.concat files_dir (Filename.basename name) in
       if Eliom.Registration.File.check_file file
       then
         (* the client-side program leaves the application to get the file *)
         Eliom.Registration.appl_self_redirect Eliom.Registration.File.send file
       else
         App.send ~code:404
           (skeleton ~title:"Not found" [p [txt "No such file."]]))
```
The handler sends only one kind of content: `Eliom.Registration.appl_self_redirect` turns the file into content that the application accepts. Do not use it for POST services, as the request would be made twice. To always send a file, register with `Eliom.Registration.File` directly. Files that need no check before being sent are better served as [static files](./#static). See `Eliom's manual`.

### How do I set the HTTP status code (404...)?

Call `Eliom.Registration.set_status` in the handler, then return the page as usual:

```ocaml
let%server article =
  App.create
    ~path:(Eliom.Service.Path ["article"])
    ~meth:(Eliom.Service.Get Eliom.Parameter.(int "id"))
    (fun id () ->
       match%lwt find_article id with
       | Some a -> Lwt.return (article_page a)
       | None ->
           Eliom.Registration.set_status `Not_found;
           Lwt.return (skeleton ~title:"Not found" [p [txt "No such article."]]))
```
For URLs that match no service, and for exceptions raised by handlers, define the error page with `Eliom.Registration.set_exn_handler`:

```ocaml
let%server () =
  Eliom.Registration.set_exn_handler (function
    | Eliom.Common.Eliom_404 ->
        App.send ~code:404
          (skeleton ~title:"Not found" [p [txt "This page does not exist."]])
    | e -> Lwt.fail e)
```
With `App.send`, the client-side program displays this page without leaving the application. Eliom then answers the unknown URLs itself: the extensions placed after `<eliom/>` in the configuration file no longer see them. The `os` template does this in `myapp.eliom`.

### How do I write a JSON service?

Between the client and the server of an Eliom application, you do not need JSON: [RPCs](./#rpc) send OCaml values. For other clients, register a service with `Eliom.Registration.String` and the `application/json` content type (here with package `yojson`):

```ocaml
let%server version =
  Eliom.Registration.String.create
    ~path:(Eliom.Service.Path ["version.json"])
    ~meth:(Eliom.Service.Get Eliom.Parameter.unit)
    (fun () () ->
       let json = `Assoc ["name", `String "myapp"; "version", `Int 2] in
       Lwt.return (Yojson.Safe.to_string json, "application/json"))
```
The tutorial [RESTful JSON API](./rest.md) gives a complete example.

### How do I make a sequence of forms (a wizard)?

Create a new service for each step, during the request, with the data of the previous steps in its closure. Unlike session data, this works with several tabs and with the back button:

```ocaml
let%server calc =
  Eliom.Service.create
    ~path:(Eliom.Service.Path ["calc"])
    ~meth:(Eliom.Service.Get Eliom.Parameter.(int "i"))
    ()

let%server sum_form i =
  (* A service for this user only, which knows [i], removed after 10 minutes
     without use. Its URL is the URL of [calc]: *)
  let sum =
    App.create_attached_get
      ~scope:Eliom.Common.default_session_scope
      ~fallback:(Eliom.Service.preapply ~service:calc 0)
      ~get_params:Eliom.Parameter.(int "j")
      ~timeout:600.
      (fun j () ->
         Lwt.return
           (skeleton ~title:"Sum"
              [p [txt (Printf.sprintf "%d + %d = %d" i j (i + j))]]))
  in
  skeleton ~title:"Sum"
    [ Form.get_form ~service:sum (fun j ->
        [ txt (string_of_int i ^ " + ")
        ; Form.input ~input_type:`Number ~name:j Form.int
        ; Form.input ~input_type:`Submit ~value:"=" Form.string ]) ]

let%server () =
  App.register ~service:calc (fun i () ->
    Lwt.return (sum_form i))
```
The fallback is used when the service no longer exists (timeout, server restarted). See `attached services` and the tutorial on [service based Web programming](./interaction.md).

## Files and images

### How do I upload a file?

Use a POST parameter of type `file`. Ocsigen Server writes the file in its upload directory, and removes it at the end of the request: move it before.

```ocaml
let%server upload_dir = "/var/www/uploads"

let%server upload =
  Eliom.Service.create
    ~path:(Eliom.Service.Path ["upload"])
    ~meth:
      (Eliom.Service.Post (Eliom.Parameter.unit, Eliom.Parameter.file "file"))
    ()

let%server () =
  App.register ~service:upload (fun () file ->
    let name =
      Filename.basename (Eliom.Request_info.get_original_filename file)
    in
    let%lwt () =
      Lwt_unix.rename
        (Eliom.Request_info.get_tmp_filename file)
        (Filename.concat upload_dir name)
    in
    Lwt.return (skeleton ~title:"Upload" [p [txt (name ^ " received.")]]))

let%server upload_form () =
  Form.post_form ~service:upload
    (fun file ->
       [ Form.file_input ~name:file ()
       ; Form.input ~input_type:`Submit ~value:"Send" Form.string ])
    ()
```
`Lwt_unix.rename` needs the upload directory and the destination on the same file system. The generated projects use `/tmp` as upload directory, which is often another file system (a `tmpfs`): change it in the configuration file, which also sets the size limits:

```xml
<uploaddir>/var/www/tmp</uploaddir>
<maxuploadfilesize>2MB</maxuploadfilesize>
<maxrequestbodysize>100MB</maxrequestbodysize>
```
(or the `~uploaddir` argument of `Ocsigen.Server.start`). To upload a file from client-side code, without changing page, create the service with `Eliom.Service.create_ocaml`, register it with `Eliom.Registration.Ocaml`, and call it with `Eliom.Client.call_ocaml_service`, giving the `File.file` of an input element; or use the picture uploader below.

### How do I upload an image, with cropping?

Ocsigen Toolkit's picture uploader shows a preview, lets the user choose the part of the image to keep, and sends it to the server, where `Os.Uploader.record_image` crops it, saves it in JPEG (with ImageMagick) under a random name, and returns this name. This is how the `os` template sets the user's avatar (`Os.User_view.upload_pic_link`, in `myapp_settings.eliom`). The widget is client-side code:

```ocaml
let%server photo_dir = "local/var/www/myapp/photos"

let%server photo_service : (unit, unit) Ot.Picture_uploader.service =
  Ot.Picture_uploader.mk_service "upload_photo" [%json: unit]

let%client photo_service = ~%photo_service

let%server () =
  Eliom.Registration.Ocaml.register ~service:photo_service
    (Os.Session.connected_fun (fun myid () ((), (cropping, file)) ->
       let%lwt name = Os.Uploader.record_image photo_dir ~ratio:1. ?cropping file in
       save_photo_name myid name))

let%client photo_form () =
  Ot.Picture_uploader.mk_form ~crop:(Some 1.)
    (Ot.Picture_uploader.ocaml_service_upload ~service:photo_service ~arg:())
```
`~crop:(Some 1.)` asks for a square, `~crop:None` for any shape. Without cropping, `record_image` keeps the file as it is, with a hard link: the upload directory must then be on the same file system as `photo_dir`. The `os` template reads this directory from the configuration file (`myapp_config.eliom`) rather than writing it in the code. The images are in the static directory, so links towards them are built as in [this question](./#static), without `~absolute:false`: they are not part of the mobile app.

## Client and server

### How do I call a server function from the client?

Declare it with `let%rpc`, giving the types of its arguments and of its result. The client calls it like an OCaml function:

```ocaml
type%shared item = {id : int; label : string} [@@deriving json]

let%rpc get_item (id : int) : item Lwt.t = Db.find_item id

let%rpc item_view (it : item) : [`Div] Eliom.Content.Html.elt Lwt.t =
  Lwt.return (div ~a:[a_class ["item"]] [txt it.label])

let%client show_item container id =
  try%lwt
    let%lwt it = get_item id in
    let%lwt node = item_view it in
    Eliom.Content.Html.Manip.appendChild container node;
    Lwt.return_unit
  with e ->
    Logs.err (fun m -> m "Cannot get item %d: %s" id (Printexc.to_string e));
    Eliom.Content.Html.Manip.appendChild container
      (p [txt "This item is not available."]);
    Lwt.return_unit
```
The server checks the values it receives: their types must have a JSON deriver (`[@@deriving json]`, from package `js_of_ocaml-ppx_deriving_json`). The result can be any value, including HTML nodes, as `item_view` shows. The syntax comes from package `ocsigen-ppx-rpc`. An RPC is a *pathless service* that anyone can call: check the rights of the user inside (see [this question](./#connected)). See `Eliom's manual`.

A call fails when the network or the server does: catch the exception, to tell the user (`Os.Msg.msg` in Ocsigen Start) and log the details. Integers are 32 bits on the client with js\_of\_ocaml, and 31 bits with wasm\_of\_ocaml: give larger values (database ids, timestamps) the type `int64`, as Ocsigen Start does for user ids.

### How do I run client-side code from server-side code?

A `[%client ...]` expression in server-side code is executed by the browser, once the page has been received. It can use server-side values with `~%`:

```ocaml
let%server counter_page () =
  let button = Eliom.Content.Html.D.button [txt "Click"] in
  let _ : unit Eliom.Client_value.t =
    [%client
      Lwt.async (fun () ->
        Js_of_ocaml_lwt.Lwt_js_events.clicks
          (Eliom.Content.Html.To_dom.of_element ~%button)
          (fun _ _ -> Lwt.return (Eliom.Lib.alert "Hello")))]
  in
  Lwt.return (skeleton ~title:"Counter" [button])
```
`~%button` refers to the same node on both sides because it is created with `D`. To react to an event, an attribute taking a client-side function is simpler, and works with `F` nodes:

```ocaml
let%shared hello_button =
  button ~a:[a_onclick [%client fun _ -> Eliom.Lib.alert "Hello"]] [txt "Click"]
```
A page can also be built by the client-side program, when the user follows a link. A `[%client ...]` expression then runs before the page is displayed: put the code that needs the page (setting the focus, measuring an element) in `Eliom.Client.onload`. Read the tutorial on [client-server widgets](./tutowidgets.md) and `Eliom's manual`.

### How do I attach OCaml values to HTML nodes?

From server-side code, with `Eliom.Content.Html.Custom_data`: the value is sent in a `data-` attribute, and the client gets it back from the DOM node:

```ocaml
let%shared item_data =
  Eliom.Content.Html.Custom_data.create_json ~name:"item" [%json: item]

let%shared item_link it =
  span ~a:[Eliom.Content.Html.Custom_data.attrib item_data it] [txt it.label]

let%client item_of_element elt =
  Eliom.Content.Html.Custom_data.get_dom elt item_data
```
`item_data` is defined on both sides (`let%shared`), and the client uses its own version: it cannot be sent with `~%`, as it contains functions. In client-side code, you usually do not need this: keep the value in the closure of the event handler, or in an OCaml map.

### How do I send notifications from the server to the clients?

With `Os.Notif`: the clients listen on a key, and the server notifies all the clients listening on that key.

```ocaml
module%server Chat_notif = Os.Notif.Make_Simple (struct
  type key = int64 (* the chat room *)
  type notification = string (* the message *)
end)

(* Anyone can call an RPC: check that the user is in the room. *)
let%server check_member myid room =
  if%lwt Db.is_member myid room
  then Lwt.return_unit
  else Lwt.fail Os.Session.Permission_denied

let%rpc listen (room : int64) : unit Lwt.t =
  Os.Session.connected_rpc
    (fun myid room ->
       let%lwt () = check_member myid room in
       Chat_notif.listen room; Lwt.return_unit)
    room

let%rpc send (room : int64) (msg : string) : unit Lwt.t =
  Os.Session.connected_rpc
    (fun myid (room, msg) ->
       let%lwt () = check_member myid room in
       Chat_notif.notify room msg; Lwt.return_unit)
    (room, msg)

let%server () =
  Os.Session.on_start_process (fun _ ->
    (* The type is written with types known on the client: *)
    let e : (int64 * string) Eliom.Eliom_react.Down.t =
      Chat_notif.client_ev ()
    in
    ignore
      [%client
        (Eliom.Lib.Dom_reference.retain Js_of_ocaml.Dom_html.window
           ~keep:(React.E.map (fun (_room, msg) -> display msg) ~%e)
         : unit)];
    Lwt.return_unit)
```
Call `Chat_notif.unlisten` when the user leaves the room. Without Ocsigen Start, use `Eliom.Notif`, on which `Os.Notif` is built. The `demo_notif.eliom` file of the `os` template, and the tutorial on [reactive applications](./tutoreact.md), show complete examples. For lower level communication, see `Eliom's manual` (channels and buses).

### How do I know that the connection to the server is lost?

With Ocsigen Start, you have nothing to do: when the server-side state of the tab is lost (server restarted, session closed or expired), the client restarts the application.

Otherwise, reading from a channel raises `Eliom.Comet.Channel_full` or `Eliom.Comet.Channel_closed` when the server has lost it, and `Eliom.Comet.set_handle_exn_function` sets what to do for other errors. The simplest is to reload the page:

```ocaml
let%client () =
  Eliom.Comet.set_handle_exn_function (fun ?exn:_ () ->
    Eliom.Client.exit_to ~service:Eliom.Service.reload_action () ();
    Lwt.return_unit)
```
An `Lwt_stream` raises its exception only once: handle it where you read the stream.

## Users and sessions

### How do I store data for one user?

In an *Eliom reference*, which has a different value for each session (scope `default_session_scope`), each tab (`default_process_scope`), or each user (`default_group_scope`):

```ocaml
let%server cart : string list Eliom.Reference.Volatile.eref =
  Eliom.Reference.Volatile.eref ~scope:Eliom.Common.default_session_scope []

let%server add_to_cart item =
  Eliom.Reference.Volatile.set cart (item :: Eliom.Reference.Volatile.get cart)
```
`Eliom.Reference.eref ~persistent:("cart", [%json: string list])` creates a reference kept in a database (with [Ocsipersist](./ocsipersist.md)), which survives a restart of the server; its `get` and `set` functions return promises. The scope of a user is a group of sessions, opened at login (Ocsigen Start does it). The tutorial [Session data](./how-to-register-session-data.md) explains all this, and `Eliom's manual` gives the details.

### How do I iterate over all the sessions or tabs of a user?

Get the state of the session group of the user, then iterate on its sessions, and on the tabs of each session:

```ocaml
let%server iter_user_tabs userid f =
  let state =
    Eliom.State.Ext.volatile_data_group_state
      ~scope:Eliom.Common.default_group_scope (Int64.to_string userid)
  in
  Eliom.State.Ext.iter_volatile_sub_states ~state (fun session ->
    Eliom.State.Ext.iter_volatile_sub_states ~state:session (fun tab ->
      f (Eliom.Reference.Volatile.Ext.get tab last_seen)))
```
Here `last_seen` is an Eliom reference of scope `default_process_scope`, and the group of a user is named `Int64.to_string userid`, as in Ocsigen Start. Outside a request, these functions need the optional argument `~sitedata` (from `Eliom.Request_info.get_sitedata` during the initialisation of the module).

### How do I restrict a page to connected users?

With Ocsigen Start, wrap the handler with `Os.Session.connected_fun`: it receives the id of the user. RPCs use `Os.Session.connected_rpc`:

```ocaml
let%server () =
  Myapp_base.App.register ~service:settings
    (Os.Session.connected_fun (fun myid () () -> settings_page myid))

let%rpc delete_photo (photo : int64) : unit Lwt.t =
  Os.Session.connected_rpc
    (fun myid photo -> Db.delete_photo ~owner:myid photo)
    photo
```
`~allow` and `~deny` restrict access to groups of users. The `Opt` versions (`Os.Session.Opt.connected_fun`) also accept users who are not connected, with `None`. In the `os` template, pages use `Myapp_page.Opt.connected_page`, which also displays a connection form when needed.

### How do I store passwords?

Ocsigen Start already does it: `Os.User.create` and the connection forms hash passwords with bcrypt. Otherwise, use `Bcrypt` from package `safepass`, and store only the hash:

```ocaml
let%server hash password = Bcrypt.string_of_hash (Bcrypt.hash password)

let%server check password stored =
  Bcrypt.verify password (Bcrypt.hash_of_string stored)
```

### How do I create a secret, unguessable identifier?

`Eliom.Lib.make_cryptographic_safe_string`, for instance `Eliom.Lib.make_cryptographic_safe_string ~len:32 ()`, for an activation link or an API key.

## Js\_of\_ocaml

The questions below are about client-side code. See also the `Js_of_ocaml manual`.

### How do I react to events?

With the functions of `Js_of_ocaml_lwt.Lwt_js_events`, which return Lwt promises. For instance, to know whether the window has the focus, and to stop the default behaviour of an event:

```ocaml
let%client has_focus =
  ref (Js_of_ocaml.Js.to_bool Js_of_ocaml.Dom_html.document##hasFocus)

let%client () =
  let open Js_of_ocaml_lwt.Lwt_js_events in
  Lwt.async (fun () ->
    focuses Js_of_ocaml.Dom_html.window (fun _ _ ->
      has_focus := true;
      Lwt.return_unit));
  Lwt.async (fun () ->
    blurs Js_of_ocaml.Dom_html.window (fun _ _ ->
      has_focus := false;
      Lwt.return_unit))

let%client prevent_drag () =
  let open Js_of_ocaml in
  Lwt.async (fun () ->
    Js_of_ocaml_lwt.Lwt_js_events.dragstarts Dom_html.document (fun ev _ ->
      Dom.preventDefault ev;
      Lwt.return_unit))
```

### How do I create a JavaScript object, or call OCaml from JavaScript?

`new%js` calls a JavaScript constructor, and `object%js` creates an object. `Js_of_ocaml.Js.export` makes OCaml functions available to JavaScript code:

```ocaml
let%client now () =
  let open Js_of_ocaml in
  let date = new%js Js.date_now in
  date##getTime

let%client () =
  let open Js_of_ocaml in
  Js.export "myLib"
    (object%js
       method greet name = Js.string ("Hello " ^ Js.to_string name)
    end)
```
JavaScript can then call `myLib.greet("Alice")`. To pass an OCaml function as a callback, use `Js_of_ocaml.Js.wrap_callback`. See the [manual page on bindings](https://ocsigen.org/js_of_ocaml/latest/manual/bindings).

### How do I load a JavaScript library?

To load it in every page, add a `js_script` element to the head ([see above](./#css)). To load it only when needed, insert a `script` element and wait for its `load` event, or its `error` event if it cannot be loaded. Keep the promise, so that the library is loaded only once:

```ocaml
(* The scripts already loaded, or being loaded *)
let%client scripts : (string, unit Lwt.t) Hashtbl.t = Hashtbl.create 8

let%client load_script url =
  match Hashtbl.find_opt scripts url with
  | Some loading -> loading
  | None ->
      let open Js_of_ocaml in
      let script = Dom_html.createScript Dom_html.document in
      script##.src := Js.string url;
      let loading =
        Lwt.pick
          [ (let%lwt _ = Js_of_ocaml_lwt.Lwt_js_events.load script in
             Lwt.return_unit)
          ; (let%lwt _ = Js_of_ocaml_lwt.Lwt_js_events.error script in
             Hashtbl.remove scripts url;
             Lwt.fail_with ("Cannot load " ^ url)) ]
      in
      Hashtbl.add scripts url loading;
      Dom.appendChild Dom_html.document##.head script;
      loading
```
The library is then reached through `Js.Unsafe.global`, or, better, through typed bindings (see [the previous question](./#js_objects)).

## Going further

### How do I use a database?

The `os` template uses PostgreSQL with PG'OCaml: the `[%pgsql]` queries are checked against the database at compile time (see `demo_pgocaml_db.ml` and `make db-update`). For a simple key-value store, use [Ocsipersist](./ocsipersist.md).

### How do I send an email?

With `Os.Email.send` in Ocsigen Start, after setting the sender with `Os.Email.set_from_addr`. It uses the `sendmail` program of the system.

### How do I translate my application?

With [ocsigen-i18n](https://github.com/ocsigen/ocsigen-i18n), used by the `os` template: translations are in a TSV file, and `[%i18n key]` inserts the text in the language of the user (see `demo_i18n.eliom`).

### How do I make a mobile application?

The `os` template builds an Android and iOS app from the same code. See [Mobile applications with Ocsigen](./mobile.md).

### How do I write logs?

With the [Logs](https://erratique.ch/software/logs) library, one source per part of your application. On the server, Ocsigen Server writes the messages in its log files (directory set in the configuration). On the client, Eliom sends them to the console of the browser, so a source can be shared:

```ocaml
let%shared src = Logs.Src.create "myapp:payment"
module%shared Log = (val Logs.src_log src : Logs.LOG)

let%shared accept_payment amount =
  Log.info (fun m -> m "payment of %d accepted" amount)
```
By default, only warnings and errors are logged. Lower the level of a source in the configuration file:

```xml
<loglevel source="myapp:payment" level="info"/>
```
or for all sources with option `-v` of `ocsigenserver` (see the `configuration file documentation`).
